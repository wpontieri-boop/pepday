## Segurança e contratos técnicos
Private schema partner_portal com 9 tabelas RLS, sem USAGE/grants diretos public/anon/authenticated/service_role. Public wrappers: partner_portal_exchange somente service_role; admin_partner_portal/admin_partner_accountant_report authenticated com guardas OWNER/AAL2/TEST/sessão existentes. search_path vazio. SECURITY DEFINER restrito/revisado, não é autorização automática para authenticated.
Token e sessão: 32 bytes criptográficos, somente SHA256 no banco; convite TTL técnico 7 dias, OTP 5 minutos, máximo 5 tentativas, cooldown 60s e até 5 desafios/convite/hora; limite 20 operações OTP/IP-hash/hora; sessão até 1h, limitada pelo convite. São parâmetros de segurança, não prazos fiscais. Token sozinho não concede dados/sessão. OTP gerado e comparado com bcrypt; falhas retornadas sem exception para preservar contador. Revogação/reemissão invalida sessões. Link inválido/vencido retorna desafio genérico sem PII.
Em TEST o OTP não é entregue a contato real: OWNER recebe um código QA por RPC protegida. Isto NÃO comprova identidade real ou posse de telefone/e-mail e não justifica liberar coleta real. Entrega externa depende de canal/credenciais/segurança autorizados.
Edge partner-portal v1 ACTIVE, verify_jwt=false porque usa autenticação customizada convite+OTP/sessão, validada por SQL service-only. URL TEST exata, origem exata, body limitado 16KB, erros genéricos, no-store/no-referrer. Nenhum endpoint administrativo/publicação real dentro da Edge. Credenciais de runtime não retornam ao cliente.
Migrations CLI locais 20261012013353_partner_portal_test e 20261012020830_partner_portal_finalization_guard; remotas 20261012015115 e 20261012020920. Aplicadas UMA vez somente TEST.
